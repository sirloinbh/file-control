# file-control

파일 컨트롤 - 내 컴퓨터 속 파일의 이름 변경, 압축 해제, 이동, 삭제 등을 자동화하는 개인 도구

외부 패키지 없이 Node.js(22 이상)만으로 동작하는 명령줄 도구 `fctl`이다.
Windows에 기본으로 있는 `fc`(파일 비교) 명령과 겹치지 않도록 이름을 `fctl`로 정했다.

## 설치

```bash
npm link                     # 어느 폴더에서나 fctl 명령을 쓸 수 있게 등록
npm unlink -g file-control   # 등록 해제
```

설치하지 않고 `node bin/fctl.js <명령>`으로 실행해도 된다.

## 명령

| 명령 | 하는 일 |
| --- | --- |
| `fctl ls [폴더]` | 폴더 내용 보기 |
| `fctl mkdir <폴더>` | 폴더 만들기 (중간 폴더도 함께) |
| `fctl write <파일> [내용]` | 파일 만들기 (내용이 없으면 표준 입력에서 읽음) |
| `fctl append <파일> [내용]` | 파일 끝에 내용 추가 |
| `fctl cat <파일>` | 파일 내용 보기 |
| `fctl rename <경로> <새이름>` | 같은 폴더 안에서 이름 바꾸기 |
| `fctl mv <원본...> <대상>` | 옮기기 (대상이 있는 폴더면 그 안으로) |
| `fctl cp <원본...> <대상>` | 복사하기 |
| `fctl rm <경로...>` | 휴지통으로 보내기 |
| `fctl unzip <압축파일> [폴더]` | 압축 풀기 (기본: 압축파일 이름의 폴더) |
| `fctl zip <압축파일> <원본...>` | 압축하기 (`.zip`, `.tar.gz` 등 확장자로 형식 결정) |
| `fctl flatten <타겟>` | 하위 폴더의 파일을 타겟 바로 아래로 옮기고 빈 폴더를 휴지통으로 보내기 |
| `fctl product-number <타겟>` | 영상 파일 이름 앞에 제품번호 넣기 |
| `fctl extract-all <타겟>` | 압축 파일마다 새 폴더에 풀기 |
| `fctl find-broken <타겟>` | 깨진 파일 찾기 (파일은 건드리지 않음) |
| `fctl remove-broken <타겟>` | 깨진 파일 목록과 확인값 보기. `--yes=확인값`을 주면 기록을 남기고 휴지통으로 |
| `fctl find-duplicates <타겟>` | 이름·제품번호나 길이가 같은 영상 묶기 (파일은 건드리지 않음) |
| `fctl remove-duplicates <타겟>` | 중복 영상 중 지울 파일 목록과 확인값 보기. `--yes=확인값`을 주면 기록을 남기고 휴지통으로 |
| `fctl collapse <타겟>` | 폴더 하나만 이어지는 구간 접기 |
| `fctl normalize <타겟>` | 파일 이름의 제품번호를 대문자로 맨 앞에 |

옵션

- `--force`: 이미 있는 파일을 덮어쓴다. 없으면 덮어쓰기 대신 오류를 내고 멈춘다.
- `--permanent`: `rm`에서 휴지통을 거치지 않고 영구 삭제한다.
- `--dry-run`: 바뀔 내용만 `[미리보기]`를 붙여 출력하고 실제로는 건드리지 않는다.

모르는 옵션은 아무것도 실행하지 않고 오류를 낸다. `-`로 시작하는 이름은 `./-이름`처럼 쓰거나 `--` 뒤에 쓴다(`fctl rename a.txt -- "-b.txt"`). `--` 뒤의 인자는 모두 옵션이 아닌 이름·내용으로 본다.

PowerShell에서는 `-b.txt`처럼 따옴표 없는 대시 이름을 `-b`와 `.txt`로 나누므로 `./-이름`을 쓰거나 이름을 따옴표로 감싼다. `npm link`로 등록한 `fctl`을 PowerShell에서 부르면 `--`가 사라질 수 있으니(`npm link` 심과 비슷하게 만든 스크립트에서 확인), `--`가 필요하면 `node bin/fctl.js`로 직접 실행한다.

`write`, `append`의 내용은 `- 항목`처럼 `-` 하나로 시작해도 되지만, `--`로 시작하는 내용과 `-h`는 `--` 뒤에 쓴다(`fctl write a.txt -- "--- 제목"`). 내용 자리의 `-dry-run` 같은 오타는 내용으로 쓰이므로 주의한다.

## 안전 장치

- 삭제는 기본적으로 휴지통으로 보내므로 되돌릴 수 있다. 대화형 세션이 아니면(서비스, 예약 작업) 영구 삭제가 되지 않도록 거부한다.
- 쓰기·이름 변경·이동·복사·압축은 대상이 이미 있으면 `--force` 없이는 덮어쓰지 않는다.
- 다른 드라이브로 옮길 때는 복사가 끝난 뒤에 원본을 지운다.
- `mv`는 전체를 먼저 검사해서 원본과 대상이 겹치거나, 여러 원본이 같은 대상으로 모이거나, 현재 폴더를 옮기려 하면 아무것도 옮기지 않고 오류를 낸다.
- `mv --force`는 기존 대상을 지우지 않고 잠시 치워 두었다가 이동이 끝난 뒤에 지운다. 이동이 실패하면 되돌린다.
- `zip`은 압축 파일 자신을 묶으려 하면 아무것도 지우기 전에 오류를 낸다.
- `zip`은 임시 이름으로 묶은 뒤 기존 압축 파일과 바꾼다. 실패하면 기존 압축 파일을 되돌린다.
- `unzip`은 암호를 묻지 않는다. 암호가 걸린 압축 파일은 실패한다.
- `zip`과 `unzip`은 경로나 묶을 폴더 안의 이름에 시스템 코드페이지에 없는 문자(이모지, 한국어 Windows의 `é`, macOS에서 온 한글 자모 등)가 있거나 이름 끝이 점이나 공백이면 실행하지 않고 오류를 낸다. `tar.exe`가 이런 이름을 다른 글자로 바꿔 다른 파일을 다룰 수 있기 때문이다.
- `--dry-run`은 없는 경로, 덮어쓰기 충돌, 자기 안으로 이동 등 실패할 작업을 미리 알려 준다. 다만 권한, 디스크 공간, 파일 잠금, Windows에서 쓸 수 없는 이름, 링크·정션을 거치는 경로, 복사하는 폴더 안쪽의 충돌, 현재 폴더나 그 상위의 이름 변경, 압축 내용의 손상과 충돌은 실제로 실행해야 알 수 있다.

## 평탄화

`fctl flatten <타겟>`은 하위 폴더의 파일을 타겟 바로 아래로 옮긴다. 먼저 `--dry-run`으로 확인할 수 있다.

- **덮어쓰지 않는다.** 이름이 겹치면 `a (2).mkv`처럼 번호를 붙인다. `--force`는 쓰지 않는다.
- **이름**: 파일이 그 폴더의 유일한 파일이고 폴더명이 더 자세하면 폴더명을 쓴다. `ABC-123 제목/abc_123.mp4`는 `ABC-123 제목.mp4`가 된다. 판단이 서지 않으면 파일 이름을 유지하고, 확장자는 바꾸지 않는다.
- **저장소는 거부한다.** 타겟 아래에 `.git`, `.hg`, `.svn`, `.jj`나 베어 저장소가 있거나 타겟이 그 안이면 아무것도 옮기지 않고 오류를 낸다. 타겟이 저장소의 일반 하위 폴더(`r/src`)면 거부하지 않는다. 저장소는 망가지지 않고 추적 파일은 git으로 되돌릴 수 있지만, 미추적 파일은 되돌릴 수 없다.
- **옮기지 않는 항목**: 링크, Windows에서 해석이 갈리는 이름(끝 점·공백, `Con.Air.mkv` 같은 장치 이름), `.fctl-old-*`·`.fctl-new-*` 잔여물, `$RECYCLE.BIN`·`System Volume Information` 안의 파일. 사유와 함께 보고한다.
- **되돌리는 기능은 없다.** `node_modules` 같은 프로그램 폴더, `desktop.ini`, `Thumbs.db`도 일반 파일처럼 옮기므로 먼저 `--dry-run`으로 확인한다.
- `--dry-run`의 이름은 실행 때 바뀔 수 있다. 앞 파일을 옮기면서 8.3 짧은 이름이 새로 차면 번호가 붙는다.
- **실패**: 잠긴 파일 등으로 한 파일이 실패해도 나머지는 계속 옮기고, 실패 목록을 보여 준 뒤 종료 코드 1로 끝난다.
- **빈 폴더**: 이번에 옮긴 파일이 있던 폴더가 비면 휴지통으로 보낸다. 그 안의 빈 폴더도 함께 간다. 원래 비어 있던 다른 폴더(`Inbox/`)는 건드리지 않는다. 건너뛰었거나 실패한 파일이 남은 폴더, 잔여물·시스템 폴더, 현재 폴더와 그 상위는 남긴다. 지우지 못한 폴더가 있으면 종료 코드 1로 끝난다. 폴더가 많으면 오래 걸린다.
- 보호 경로(`C:\Windows`, 사용자 폴더 자체, `AppData` 등)는 타겟으로 쓸 수 없다.

## 제품번호 넣기

`fctl product-number <타겟>`은 타겟 아래 영상 파일의 이름 앞에 제품번호를 넣는다. `ABC-123 제목/video.mp4`는 `ABC-123 제목/ABC-123 video.mp4`가 된다. 파일을 옮기지는 않는다. 먼저 `--dry-run`으로 확인할 수 있다.

- **형식**: `ABC-123`처럼 영문 2~6자, 하이픈, 숫자 2~5자. 자세한 규칙은 `src/product.js`에 있다.
- **대상**: 영상 확장자의 파일만 바꾼다. `.ts`, `.mts`는 내용이 전송 스트림일 때만 영상으로 본다. TypeScript 소스를 바꾸지 않기 위해서다.
- **찾는 곳**: 파일명, 메타데이터 제목, 폴더명(타겟 아래, 가까운 폴더부터), 코멘트 순이다. 메타데이터는 MP4 계열(`.mp4`, `.m4v`, `.mov`, `.3gp`)과 `.mkv`, `.webm`만 읽는다.
- **이미 번호가 있으면** 위치에 관계없이 건너뛴다. 넣으려는 번호와 같으면 대소문자가 다르거나 글자가 붙어 있어도(`ABC-123-01`, `abc-123`) 있는 것으로 본다.
- **파일명의 소문자 말**(`trip-2023`, `intro-01`)은 번호인지 확실하지 않다. 제목, 폴더, 코멘트에 다른 번호가 있으면 고르지 않고 엇갈림으로 보고한다.
- **못 찾으면** 건드리지 않고 목록으로 보고한다. 제목과 폴더의 번호가 엇갈려도 고르지 않고 보고한다. 링크는 바꾸지 않고 보고한다.
- **덮어쓰지 않는다.** 같은 이름이 있으면 건너뛰고 보고한다.
- **되돌리는 기능은 없다.** OneDrive 온라인 전용 파일은 메타데이터를 읽을 때 내려받기가 일어날 수 있다. `.ts`, `.mts`는 이름과 상관없이 앞부분을 읽으므로 번호가 없는 소스 파일에서도 일어날 수 있다.

## 파일 이름 정규화

`fctl normalize <타겟>`은 타겟 아래 파일 이름의 제품번호를 대문자로 맨 앞에 옮긴다. `영상 ABC-123.mp4`는 `ABC-123 영상.mp4`가 된다. 파일을 옮기지는 않는다. 먼저 `--dry-run`으로 확인할 수 있다.

- **번호가 아닌 말과 확장자는 바꾸지 않는다.** 번호를 뺀 자리의 구분 문자와 빈 괄호만 정리한다. `.en.srt`, `.7z.001` 같은 꼬리는 끊지 않는다.
- **소문자 말은 기본으로 바꾸지 않는다.** `trip-2023.mp4`, `node-22.1.0.msi`처럼 번호가 아닐 수 있어서 어떻게 바뀔지 보고만 한다. `--include-lowercase`를 주면 바꾼다.
- **덮어쓰지 않는다.** 결과가 기존 항목이나 다른 파일의 결과와 겹치면 어느 쪽도 바꾸지 않고 보고한다.
- **대소문자만 바뀌는 이름**은 임시 이름을 거쳐 바꾼다.
- **그대로 두는 것**: 번호가 여럿인 이름, 숨김 파일, `~$`로 시작하는 임시 파일, 끝이 점이나 공백인 이름, 링크, 잔여물, 시스템 폴더 안의 파일. 이 중 숨김 파일, 임시 파일, 끝이 점이나 공백인 이름은 보고하지 않는다.
- **저장소가 들어 있으면 전체를 거부한다.** 베어 저장소도 같다. ref와 객체 이름이 바뀌면 저장소가 깨진다. 타겟이 `.git`이나 베어 저장소 폴더 안이어도 거부한다. `work/src`처럼 작업 트리의 일반 하위 폴더는 git으로 되돌릴 수 있어 바꾼다.
- **먼저 미리보기로 확인한다.** 파일 종류를 가리지 않으므로 받는 중인 파일(`.crdownload`, `.part`), 프로그램 폴더 안의 파일, 웹 페이지와 그 `_files` 폴더처럼 이름으로 이어진 파일도 바꾼다. 다른 프로그램이 파일을 찾지 못하게 될 수 있다.
- **되돌리는 기능은 없다.**

## 연속 폴더 접기

`fctl collapse <타겟>`은 폴더 안에 폴더 하나만 이어지는 구간을 접는다. `a/b/c/파일`은 `a/파일`이 된다. 먼저 `--dry-run`으로 확인할 수 있다.

- **맨 위 폴더 이름을 남긴다.** 가운데 폴더 이름은 사라진다.
- **한 단계에 항목이 여럿이면 구조를 유지한다.** 숨김 파일도 항목으로 센다. 그 아래에 이어지는 구간은 따로 접는다. 타겟 자신은 접지 않는다. 끝이 빈 폴더인 구간은 건드리지 않는다.
- **이름이 충돌하지 않는다.** 맨 아래 폴더를 통째로 옮기므로 파일 하나하나를 옮기지 않는다.
- **제품번호가 사라지면 접지 않는다.** 가운데 폴더 이름의 제품번호가 맨 위 폴더 이름에 없고, 안쪽의 모든 영상(영상이 없으면 모든 파일) 이름에도 없으면 건너뛰고 보고한다. 영상이 있는 폴더는 `product-number`를 먼저 실행하면 접을 수 있다. `src/product.js`가 인식하는 형식만 보호한다.
- **치운 빈 폴더는 휴지통으로 보낸다.** 보내지 못하면 접은 결과를 두고 `.fctl-old-*` 폴더가 남았다고 보고한다.
- **건너뛰는 것**: 잔여물, 시스템 폴더, 링크가 든 구간과, 그런 항목을 안에 품은 구간. 저장소가 들어 있으면 전체를 거부한다. `flatten`과 같다.
- **안쪽 구간이 실패하면 그 구간을 품은 위 구간도 접지 않는다.**
- **폴더 속성은 맨 아래 폴더의 것이 된다.** 맨 아래 폴더가 숨김이면 접은 폴더도 숨김이 된다.
- **되돌리는 기능은 없다.**

## 깨진 파일 찾기

`fctl find-broken <타겟>`은 타겟 아래 파일을 살펴 보고만 한다. 파일은 건드리지 않는다.

- **깨짐**: 크기가 0인 영상·이미지·문서·압축 파일, 앞부분이 모두 0이거나 내용이 웹 페이지인 파일, 잘리거나 구조가 손상된 영상과 압축 파일. `.tar` 계열은 `tar.exe`가 잘렸거나 손상됐다고 알린 경우다.
- **의심**: 정상일 수 있는 파일. 앞 바이트가 확장자와 맞지 않는 파일(이름만 바뀌었거나 암호 걸린 Office 문서처럼 다른 포장을 쓴 경우), 구조는 온전한데 뒤에 다른 데이터가 붙은 파일, 형식을 모르는 빈 파일(`__init__.py`, `.gitkeep` 등)이다.
- **판단 못함**: 잠겼거나 읽지 못한 파일, `tar.exe`가 손상이 아닌 이유로 실패한 파일(코드페이지에 없는 이름 등), 항목이 너무 많거나 읽는 데 10분을 넘는 압축 파일, 박스가 아주 많은 조각 MP4. 깨진 파일로 보지 않는다.
- **보는 형식**: `.mp4`, `.m4v`, `.m4a`, `.mov`, `.3gp`, `.3g2`, `.mkv`, `.mka`, `.webm`, `.avi`, `.wav`, `.webp`, `.wmv`, `.wma`, `.asf`, `.flv`, `.flac`, `.ogg`, `.oga`, `.ogv`, `.opus`, `.jpg`, `.jpeg`, `.jfif`, `.png`, `.gif`, `.bmp`, `.tif`, `.tiff`, `.pdf`, `.zip`과 Office 문서(`.docx`, `.xlsx`, `.pptx`, `.odt`, `.ods`, `.odp`), `.epub`, `.jar`, `.apk`, `.7z`, `.rar`, `.gz`, `.bz2`, `.xz`, `.tar`와 그 압축 형식. 다른 파일은 크기가 0인지만 본다.
- **빼는 것**: 제거 기록(`fctl-removed-*.json`)과 저장소 폴더(`.git` 등) 안은 조용히 뺀다. 링크, 잔여물, 시스템 폴더 안의 파일은 건너뛰었다고 보고한다.
- **잡지 못하는 손상**: 앞쪽 구조만 본다. 영상 데이터 안의 손상, 이미지와 PDF의 본문, `.zip`과 `.7z` 항목의 내용(CRC), `.rar`와 `.gz`, `.bz2`, `.xz` 단독 파일의 내용은 확인하지 않는다. 압축 tar도 본문이 변한 것은 놓칠 수 있다. 깨짐이 나오지 않았다고 온전하다는 뜻은 아니다.
- **받는 중인 파일**: 끝까지 받지 못한 영상은 대개 깨짐으로 나온다. 받는 중이 아닌지 확인한다. 다만 미리 크기를 잡고 받는 도구의 파일(앞은 정상, 뒤는 0)은 `moov`가 앞에 있는 MP4, 크기가 정해진 MKV, `.7z`, `.tar`에서 정상으로 나올 수 있다.
- **깨짐으로 나오는 정상 파일**: GNU 다중 볼륨 `.tar`의 조각, 파일 뒤에 70KB 넘게 덧붙은 `.zip`은 잘린 파일과 구분할 수 없다. `<html`로 시작하는 `.xlsx`(HTML 표를 엑셀 이름으로 내보낸 파일)도 깨짐으로 나온다.
- **읽기 비용**: `.tar`와 그 압축 형식은 끝까지 읽어 크면 오래 걸린다. OneDrive 온라인 전용 파일은 읽을 때 내려받기가 일어날 수 있다.

## 깨진 파일 제거

`fctl remove-broken <타겟>`은 `find-broken`에서 깨짐으로 나온 파일을 휴지통으로 보낸다.

- **확인값 없이는 지우지 않는다.** 먼저 목록과 확인값을 보여 준다. 위 "깨짐으로 나오는 정상 파일"이 있는지 확인한 뒤 `--yes=확인값`을 붙여 다시 실행한다. `--dry-run`을 함께 주면 지우지 않는다.
- **본 목록이 그대로일 때만 지운다.** 다시 판별해 지울 파일의 경로, 사유, 크기, 시각, 파일 번호가 하나라도 달라지거나 지울 파일이 늘고 줄면 확인값이 달라진다. 그러면 아무것도 지우지 않고 새 목록과 새 확인값을 보여 준 뒤 종료 코드 1로 끝난다.
- **기록을 먼저 남긴다.** 타겟에 `fctl-removed-날짜-시각.json`(경로, 크기, 사유)을 쓰고 나서 옮긴다. 기록을 남기지 못하면 아무것도 지우지 않는다. 기록은 제거 대상을 적은 것이고 결과는 적지 않으므로, 옮기지 못한 파일은 명령 출력에서 확인한다.
- **의심과 판단 못함은 지우지 않는다.**
- **저장소는 다루지 않는다.** 타겟이 저장소 폴더이거나 저장소를 담고 있으면 거부한다. 저장소의 일반 하위 폴더는 막지 않는다.
- **남기는 파일**: 수정, 생성, 변경 시각 중 가장 늦은 것이 5분 안인 파일(받는 중이거나 방금 복사했을 수 있음), 시각이 미래인 파일, 판별한 뒤 바뀐 파일, 지울 수 없는 이름의 파일.
- **영구 삭제를 피하려고 남기는 파일**: 휴지통 용량을 넘는 큰 파일이나 휴지통이 없는 볼륨에서는 Windows가 묻지 않고 영구 삭제할 수 있다(#81, 시험하지 못함). 그래서 1GB 이상인 파일과, 고정 디스크가 아니거나 종류를 확인하지 못한 볼륨의 파일은 지우지 않고 남긴다. 이 기준으로 막지 못하는 경우가 있다(#100). 휴지통을 껐거나 용량이 1GB보다 작은 볼륨(기본 설정이면 약 20GB 미만), 합계가 휴지통 용량을 넘어 오래된 항목이 비워지는 경우, 고정 디스크로 보이는 USB 외장 디스크와 가상 드라이브, 볼륨 마운트 폴더가 그렇다.
- **대화형 세션에서만 지운다.** 비대화형 실행이면 기록을 남기기 전에 멈춘다.
- **OneDrive 폴더**: 동기화가 파일의 변경 시각을 바꾼다. 그래서 동기화 중에는 5분 보호가 늘어나거나 확인값이 어긋날 수 있다. 지우지 않는 쪽으로 동작하므로 잠시 뒤 다시 실행한다.
- **종료 코드**: 휴지통으로 보내지 못한 파일이 있거나, 확인값이 맞지 않거나, 지울 파일이 있는데 `--yes`에 값을 붙이지 않았으면 1이다. `--yes` 없는 목록 보기와 남긴 파일만 있는 경우는 0이다.

## 중복 영상 찾기

`fctl find-duplicates <타겟>`은 타겟 아래 영상 파일을 이름 기준과 길이 기준으로 묶어 중복 후보를 보여 준다. 파일은 건드리지 않는다. 파일마다 크기, 해상도, 길이를 함께 보여 주고, 묶음마다 남길 파일 하나에 `[남김: 고른 까닭]`을 붙인다. 제거는 `remove-duplicates`로 한다(아래).

- **제품번호로 묶기**: 이름에 대문자 제품번호(`ABC-123`)가 하나 있으면 번호로 묶는다. 확장자, 폴더, 화질 표시, 제목, `(1)` 꼬리가 달라도 같은 묶음이다. `ABC-123.mp4`와 `sub/[FHD] ABC-123 제목 1080p.mkv`가 그렇다.
- **조각은 따로 묶는다**: 다른 영상을 한 묶음에 넣지 않도록 조각 표시를 넓게 본다. 번호를 뺀 나머지를 낱말로 나눠, 낱말 속의 숫자(`CD2`, `part 1`, `-1`, `[2]`, `제목 3`, `Episode 01`, `1.5`), 원문자 숫자(`①`), 영문 한 글자 낱말(`ABC-123 B`, `(A)`, `[A]`, `Title A`, `Part I`), 두 글자 이상의 로마 숫자(`II`, `xiv`)와 로마 숫자 글자(`Ⅲ`), `前編`·`後編`·`上巻`·`下巻`·`상`·`하편`·`전편`·`第一話`를 조각으로 본다. 화질·코덱 표시(`1080p`, `60fps`, `10bit`, `4K`, `x264`, `HEVC`, `AAC2` 등)와 끝의 `(1)`, 복사본 꼬리는 빼고 본다. `part 01`, `-1`, `①`은 같은 조각 1이고 `III`, `Ⅲ`, `③`은 같은 조각 3이다. 그래서 `ABC-123 CD1`, `ABC-123 CD2`, `ABC-123`은 서로 다른 묶음이다. 대신 제목에 숫자나 한 글자 낱말이 든 같은 영상(`ABC-123 2023`, `ABC-123 A Day`)이나 `5.1ch`, `AAC2.0`처럼 점이 든 음향 표시가 붙은 같은 영상은 따로 묶여 중복을 놓칠 수 있다.
- **번호가 없으면 이름으로 묶기**: 확장자를 뺀 이름에서 대소문자, 전각, 조합형 한글, 공백·점·밑줄·하이픈의 차이와 탐색기의 복사본 꼬리(` - 복사본`, ` - Copy (2)`)를 무시한다. `My Movie.mp4`, `my_movie.MKV`, `My Movie - 복사본.avi`가 같은 묶음이다. `My Movie (1).mp4`는 다른 영상일 수 있어 묶지 않는다.
- **묶지 않는 것**: 서로 다른 번호가 여럿 든 이름은 "번호가 여럿"으로 보고한다. 소문자 번호(`abc-123`)는 번호로 보지 않고 이름으로 묶는다. 먼저 `normalize --include-lowercase`로 바꾸면 번호로 묶인다.
- **보는 파일**: `product-number`와 같은 영상 확장자다. `.ts`, `.mts`는 내용이 MPEG-TS일 때만 본다. 링크, 잔여물, 시스템 폴더 안의 파일은 건너뛰었다고 보고하고, 저장소 폴더(`.git` 등) 안은 조용히 뺀다. 제거 기록(`fctl-removed-*.json`)은 영상이 아니라 보지 않는다.
- **이름은 내용을 보지 않는다**: 이름 묶음은 내용이 같은지 보지 않는다. 그래서 다른 영상이 한 묶음에 들 수 있다. 같은 묶음의 길이와 해상도를 비교해 본다. 아래 묶음에는 파일 줄 다음에 `주의:` 줄을 붙이고, 마지막 줄에 "확인 필요" 묶음 수로 센다(#103).
  - **카메라·순번처럼 흔한 이름**: `IMG_0001.MOV`, `GH010001.MP4`, `DJI_0001.MP4`, `1.mp4`, `REC-0001.mp4`처럼 다른 폴더의 다른 영상이어도 이름이 같아지는 묶음. 판정 기준은 아래 `remove-duplicates`와 같다. "주의: 카메라·순번처럼 흔한 이름이라 이름이 같아도 다른 영상일 수 있습니다."
  - **번호는 같은데 제목이 다른 묶음**: 제품번호처럼 보이는 말(`WWE-2023 Raw`와 `WWE-2023 SmackDown`, `IPHONE-15 review`와 `IPHONE-15 unboxing`)은 같은 번호로 묶인다. 번호를 뺀 나머지에서 숫자, 조각 표시, 화질·코덱·배포 표시(`1080p`, `FHD`, `HEVC`, `자막` 등), 복사본 꼬리를 뺀 낱말을 제목으로 본다. 제목이 있는 두 파일에서 어느 쪽 낱말도 다른 쪽에 모두 들어 있지 않으면 "주의: 번호는 같지만 제목이 서로 달라 다른 영상일 수 있습니다."를 붙인다. `좋은 영화`와 `좋은 영화 감독판`은 같은 제목이고, `WWE Raw`와 `WWE SmackDown`처럼 일부만 겹치면 다른 제목이다. 한쪽에만 제목이 있으면(`ABC-123.mp4`와 `ABC-123 제목.mkv`) 다르다고 보지 않는다. 같은 영상인데 제목을 다른 말(다른 언어, 낱말을 더하고 뺀 제목 등)로 붙인 파일도 다르다고 볼 수 있다.
  - **길이가 다른 묶음**: 아래 "길이가 다른 이름 묶음은 주의를 붙인다"를 보라.
- **길이로 묶기**: 이름이 달라도 길이 차이가 1초 이내이고 화면 비율(보이는 가로÷세로)이 3% 이내인 영상을 "길이가 같은 영상"으로 묶는다. 보고의 화면 비율은 소수 첫째 자리까지 쓴다. 해상도와 크기는 달라도 된다. 같은 영상을 다시 인코딩하면 둘 다 달라지기 때문이다. 크기까지 같으면 "크기도 같음"을 붙인다.
- **길이로 묶지 않는 것**: 60초 미만인 영상(짧은 클립은 길이가 우연히 같은 경우가 많다), 길이나 해상도를 읽지 못한 영상. 길이는 `.mp4`, `.m4v`, `.mov`, `.3gp`, `.mkv`, `.webm`에서만 읽는다. `.avi`, `.wmv`, `.flv`, `.ts` 등은 "길이 모름"으로 센다. 묶음 안의 어느 두 파일도 1초 넘게 차이 나지 않도록, 가장 짧은 파일에서 1초까지만 넣는다. `.mp4`, `.mkv`처럼 길이를 읽을 수 있는 형식인데 길이나 해상도를 읽지 못한 파일(구조가 깨진 파일, 길이를 적지 않은 조각 MP4나 녹화가 중단된 MKV/WebM, 영상 트랙이 없는 파일)은 "길이·해상도 못 읽음"으로 사유와 함께 보여 준다.
- **화면 비율은 보이는 크기로 계산한다**(#106): 해상도는 저장된 값으로 보여 주고, 회전이나 화소 비율 때문에 보이는 크기가 다르면 `1920x1080(보이는 크기 1080x1920)`처럼 함께 쓴다.
  - **회전**: MP4/MOV의 트랙 회전 정보(tkhd 행렬)가 90도나 270도이면 너비와 높이를 바꾼다. 그래서 휴대폰이 가로로 저장하고 세로로 표시하는 영상(1920x1080 + 90도)은 세로로 다시 저장한 사본(1080x1920)과 묶이고, 길이가 비슷한 가로 영상과는 묶이지 않는다.
  - **화소 비율**: MP4/MOV의 `pasp`가 있으면 너비에 곱한다. MKV/WebM은 `DisplayWidth`/`DisplayHeight`가 있으면 그 비율을 쓴다(단위가 화소, cm, 인치, 화면 비율일 때). DVD 16:9(720x480, 보이는 크기 853x480)는 16:9 영상과 묶인다.
  - **3% 이내면 같다**: 반올림한 칸으로 비교하면 1920x816과 1920x818처럼 경계에 걸친 같은 영상이 갈리므로, 넓은 쪽이 좁은 쪽보다 3% 이내로 넓으면 같다고 본다. 16:9(1.78)와 1.85:1은 4% 가까이 달라 묶지 않는다. 한 묶음 안의 어느 두 파일도 3% 넘게 다르지 않도록, 묶음의 모든 파일과 3% 이내인 파일만 넣는다.
  - **보지 않는 것**: MKV의 회전(Projection) 정보, 잘라 낼 화소(PixelCrop), 영상 데이터 안의 화소 비율은 보지 않는다.
- **되풀이하지 않는다**: 길이 묶음의 파일이 모두 한 이름 묶음에 이미 들어 있으면 길이 묶음으로는 다시 보여 주지 않는다.
- **길이가 같아도 다른 영상일 수 있다**: 길이가 정해진 방송 녹화, 같은 길이로 자른 영상은 내용이 달라도 묶인다. 내용(영상 데이터)은 비교하지 않는다.
- **남길 파일 고르기**: 아래 기준을 차례로 보고, 기준마다 가장 나은 파일만 다음 기준으로 넘긴다.
  1. `.mp4`, `.mkv`처럼 길이를 읽을 수 있는 형식인데 길이나 해상도를 읽지 못한 파일은 깨졌을 수 있어 뒤로 뺀다. `.avi`처럼 읽지 않는 형식은 빼지 않는다.
  2. 1에서 남은 파일 중 길이를 아는 가장 긴 파일보다 1초 넘게 짧은 파일은 덜 받았거나 잘린 사본일 수 있어 뒤로 뺀다.
  3. 해상도(가로×세로 화소 수)가 가장 높은 파일. 해상도를 모르는 파일은 아는 파일보다 뒤다.
  4. 크기가 가장 큰 파일.
  5. 이름이 가장 짧은 파일. 복사본 꼬리(` - 복사본`, ` (1)`, ` copy`)가 붙지 않은 원래 파일일 가능성이 크다.
  6. 경로 순으로 첫 파일(이름 묶음의 보고 순서와 같다. 길이 묶음은 길이 순으로 보여 주므로 다를 수 있다).
- **길이가 다른 이름 묶음은 주의를 붙인다**: 이름 묶음에서 길이를 아는 파일끼리 1초 넘게 다르면 "주의: 길이가 서로 달라 같은 영상이 아닐 수 있습니다."를 보여 준다. 남길 파일은 그래도 고르지만, 나머지가 정말 사본인지 확인해야 한다(#103).
- **묶음마다 따로 고른다**: 한 파일이 이름 묶음과 길이 묶음에 함께 들면, 한쪽에서는 남기고 다른 쪽에서는 남기지 않을 수 있다. 화질은 해상도와 크기로만 판단한다. 코덱(H.264, HEVC 등)과 비트레이트는 보지 않는다.
- **읽기 비용**: 영상 머리 구조만 읽지만, OneDrive 온라인 전용 파일은 읽을 때 내려받기가 일어날 수 있다.

## 중복 영상 제거

`fctl remove-duplicates <타겟>`은 `find-duplicates`의 이름 묶음마다 남길 파일 하나를 두고, 그 파일의 사본을 휴지통으로 보낸다.

- **확인값 없이는 지우지 않는다.** 먼저 묶음마다 남길 파일, 지울 파일, 남기는 파일과 확인값을 보여 준다. 목록을 확인한 뒤 `--yes=확인값`을 붙여 다시 실행한다. `--dry-run`을 함께 주면 지우지 않는다.
- **이름과 길이가 모두 맞는 사본만 지운다.** 이름 묶음의 파일 중 남길 파일과 길이 차이가 1초 이내이고 화면 비율이 같은(`find-duplicates`와 같은 기준으로 보이는 크기에서 3% 이내) 파일만 지운다. 이름만 같은 다른 영상(같은 번호의 예고편, 제품번호처럼 보이는 `WWE-2023 Raw`와 `WWE-2023 SmackDown`)은 길이나 비율이 다르면 남긴다. 길이나 해상도를 모르는 파일(`.avi` 등)과 60초 미만인 파일도 같은 영상인지 확인할 수 없어 남긴다. 남길 파일의 길이를 모르면 그 묶음은 아무것도 지우지 않는다. 묶음에 길이가 다른 파일이 있으면 `주의:` 줄을 함께 보여 준다.
- **번호는 같은데 제목이 다른 파일은 지우지 않는다.** 번호 묶음에서 남길 파일과 제목이 다른(`find-duplicates`와 같은 기준) 파일은 길이와 화면 비율이 같아도 남긴다. 길이가 정해진 방송 녹화(`WWE-2023 Raw`와 `WWE-2023 SmackDown`이 모두 3시간)가 그렇다(#103). 제목이 다른 파일이 섞인 묶음에서는 남길 파일과 지울 파일에 모두 제목이 있고 제목 낱말이 똑같을 때만 지운다(`XYZ-999 좋은 영화.mp4`와 `XYZ-999 좋은 영화 1080p.mp4`). 남길 파일이 `WWE-2023.mp4`처럼 제목이 없거나 `WWE-2023 WWE.mp4`처럼 두 제목에 모두 들어 있으면 Raw와 SmackDown 중 어느 것의 사본인지 몰라 둘 다 남긴다. 제목이 다른 파일이 없는 묶음에서는 한쪽에 제목이 없거나(`QRS-100 제목.mp4`와 `QRS-100.mp4`) 낱말을 더한 제목(`좋은 영화`와 `좋은 영화 감독판`)이어도 지운다.
- **카메라·순번처럼 흔한 이름은 지우지 않는다.** 이름 묶음의 기준값이 앞의 영문 낱말 하나(10글자까지)를 빼면 숫자 위주의 낱말(`e0001`, `000001f`처럼 앞에 영문 4글자, 뒤에 2글자까지)과 영문 1~2글자 낱말뿐인 묶음(`IMG_0001.MOV`, `IMG_E0001.MOV`, `GH010001.MP4`, `DJI_20230101123456_0001_D.MP4`, `FILE0001.MOV`, `VID_20230101_123456.mp4`, `20230101_123456_F.mp4`, `1.mp4`)은 길이와 화면 비율이 같아도 남긴다. 블랙박스 조각이나 시간으로 나눈 녹화는 길이가 정해져 있어, 다른 SD카드의 다른 영상이 같은 이름·같은 길이일 수 있다(#103). `Video 1.mp4`, `Joker 2019.mp4`, `EP01.mp4`처럼 낱말 하나와 숫자로 된 사람이 붙인 이름도 여기에 들어 남는다. 대문자와 하이픈으로 된 녹화기 카운터는 제품번호로 묶이므로, 접두어가 `REC`, `CAM`, `MOVI`, `FRONT`, `REAR`, `EVT`, `PARK`, `NORMAL` 등 정해 둔 목록에 있으면 그 번호 묶음도 남긴다(`REC-0001.mp4`, #110). 목록에 없는 접두어의 카운터는 제품번호처럼 다뤄 지워질 수 있다.
- **남길 파일이 온전해 보일 때만 지운다.** 남길 파일은 해상도와 크기로 고르므로, 해상도가 높은 덜 받은 파일이 남길 파일이 될 수 있다. 그래서 남길 파일에 `find-broken`과 같은 판별을 하고, 깨짐이나 의심이 나오면(잘린 파일, 위치표가 없는 파일 등) 그 묶음은 지우지 않는다. 1MB 이상이면 16군데에서 4KB씩 읽어, 0으로만 채워진 구간이 있으면 크기만 미리 잡아 둔 채 멈춘 내려받기일 수 있어 지우지 않는다(#109). 데이터 전체를 읽지는 않으므로 일부만 손상된 파일은 잡지 못한다. 목록에서 남길 파일을 확인한 뒤 실행한다.
- **길이만 같은 묶음은 지우지 않는다.** 이름이 다르면 길이가 같아도 다른 영상일 수 있다. 개수만 알리고 `find-duplicates`로 보게 한다. 그래서 이름 묶음끼리는 파일이 겹치지 않아, 한 묶음에서 남긴 파일이 다른 묶음에서 지워지는 일이 없다.
- **남길 파일을 지키며 지운다.** 남길 파일이 5분 안에 바뀌었거나 시각이 미래이면 그 묶음은 지우지 않는다. 확인값에는 남길 파일의 시각도 들어가므로, 확인값을 만든 뒤 남길 파일이 바뀌면 아무것도 지우지 않는다. 지우는 중에도 사본 하나마다 남길 파일이 그대로 있는지 다시 보고, 없어졌거나 바뀌었으면 그 사본을 지우지 않고 실패로 보고한다.
- **기록을 먼저 남긴다.** 타겟에 `fctl-removed-날짜-시각.json`을 쓰고 나서 옮긴다. 항목마다 경로, 크기, 사유와 `details`에 남긴 파일(`keep`)과 묶음 이름(`group`)을 적는다.
- **나머지 안전 장치는 `remove-broken`과 같다.** 저장소는 다루지 않는다. 5분 안에 바뀐 사본, 1GB 이상인 사본, 고정 디스크가 아닌 볼륨의 사본은 남긴다(#81, #100). 대화형 세션에서만 지운다. 종료 코드도 같다. 영상은 1GB를 넘는 경우가 많아, 지금은 큰 사본이 대부분 "남김"으로 나온다.

## 압축 파일 모두 풀기

`fctl extract-all <타겟>`은 타겟 아래 압축 파일(`.zip`, `.tar`, `.tar.gz`, `.tgz`, `.tar.bz2`, `.tbz2`, `.tar.xz`, `.txz`, `.7z`, `.rar`)을 각각 옆의 새 폴더에 푼다. `a.zip`은 `a/`가 된다. 먼저 `--dry-run`으로 확인할 수 있다.

- **압축 파일은 기본으로 남긴다.** 풀려 나온 압축 파일을 다시 풀지도 않는다.
- **`--remove-archives`**: 정상으로 풀린 `.zip`, `.7z`를 휴지통으로 보낸다. 건너뛰거나 실패한 압축 파일은 지우지 않는다. 그래서 이미 풀어 둔 폴더가 있으면 원본도 남는다.
- **이 옵션으로도 남기는 경우**: 아래는 풀기만 하고 "남김"으로 보고한다.
  - 다른 형식(`.tar`, `.tar.gz`, `.tgz`, `.tar.bz2`, `.tbz2`, `.tar.xz`, `.txz`, `.rar`). `tar.exe`가 손상을 잡지 못하거나 일부를 읽지 않거나, 잡는지 확인하지 못했다.
  - 내용이 확장자와 다른 파일, 끝이 잘렸거나 앞뒤에 다른 데이터가 붙은 `.zip`, 뒤에 다른 데이터가 붙은 `.7z`, 분할 압축 조각, Zip64 형식의 `.zip`.
  - 원래 이름 그대로 풀렸는지 확인하지 못한 경우. `:`나 `?`가 든 이름, UTF-8 표시가 없는 비ASCII 이름의 `.zip`, 비ASCII 이름의 `.7z`가 해당한다. 한국어 도구나 `fctl zip`으로 만든 한글 이름의 `.zip`도 여기에 들 수 있다.
- **휴지통 주의**: 휴지통 용량을 넘는 큰 파일이나 휴지통이 없는 볼륨에서는 Windows가 묻지 않고 영구 삭제할 수 있다. 시험하지는 못했다. 내용은 새 폴더에 풀려 있다.
- **합치지 않는다.** 같은 이름의 폴더나 파일이 있으면 건너뛰고 보고한다. 그래서 다시 실행해도 또 풀리지 않는다.
- **전부 풀린 것만 내놓는다.** 임시 폴더(`.fctl-new-*`)에 푼 뒤 이름을 바꾼다. 실패하면 임시 폴더를 지우고 실패로 보고한다.
- **실패로 보는 경우**: 깨진 압축 파일, 암호가 걸린 압축 파일, 항목이 하나도 없는 파일, `..`로 타겟 밖을 가리키는 항목, 이름이 겹쳐 일부를 잃는 항목(대소문자만 다른 경우 포함), `con.txt`나 끝이 점인 이름처럼 Windows에서 다르게 해석되는 이름, 링크와 장치 항목.
- **잡지 못하는 손상**: `.tar.gz`는 본문이 일부 변해도 성공할 수 있고, `.tar`는 항목 경계에서 잘리면 남은 항목만 풀고 성공한다. `.zip`도 끝이 잘리거나 다른 파일이 이어 붙으면 일부만 풀고 성공할 수 있다. 풀기는 성공으로 보고하되 위 기준에 따라 원본은 지우지 않는다.
- **미리보기는 목록만 읽는다.** 암호, 이름 겹침, 쓸 수 없는 이름은 실제로 풀어야 알 수 있다.
- **항목 이름**: `tar.exe`가 처리한다. 이모지처럼 코드페이지에 없는 문자가 있거나, Linux·macOS에서 만든 tar에 UTF-8 이름이 그대로 들어 있으면 실패할 수 있고(미리보기는 통과할 수 있다), `:`, `?`, `*` 같은 문자는 `_`로 바뀌거나 이름 앞부분이 사라질 수 있다.
- **크기 제한은 없다.** 풀린 크기를 미리 확인하지 않으므로 디스크가 찰 수 있다. OneDrive 온라인 전용 압축 파일은 읽을 때 내려받기가 일어날 수 있다.
