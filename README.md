# file-control

파일 컨트롤 - 내 컴퓨터 속 파일의 이름 변경, 압축 해제, 이동, 삭제 등을 자동화하는 개인 도구

외부 패키지 없이 Node.js(22 이상)만으로 동작하는 명령줄 도구 `fctl`이다.
Windows에 기본으로 있는 `fc`(파일 비교) 명령과 겹치지 않도록 이름을 `fctl`로 정했다.

## 설치

```bash
npm link                     # 어느 폴더에서나 fctl 명령을 쓸 수 있게 등록
npm unlink -g file-control   # 등록 해제
```

설치하지 않고 `node bin/fctl.js <명령>`으로 실행해도 된다.

## 명령

| 명령 | 하는 일 |
| --- | --- |
| `fctl ls [폴더]` | 폴더 내용 보기 |
| `fctl mkdir <폴더>` | 폴더 만들기 (중간 폴더도 함께) |
| `fctl write <파일> [내용]` | 파일 만들기 (내용이 없으면 표준 입력에서 읽음) |
| `fctl append <파일> [내용]` | 파일 끝에 내용 추가 |
| `fctl cat <파일>` | 파일 내용 보기 |
| `fctl rename <경로> <새이름>` | 같은 폴더 안에서 이름 바꾸기 |
| `fctl mv <원본...> <대상>` | 옮기기 (대상이 있는 폴더면 그 안으로) |
| `fctl cp <원본...> <대상>` | 복사하기 |
| `fctl rm <경로...>` | 휴지통으로 보내기 |
| `fctl unzip <압축파일> [폴더]` | 압축 풀기 (기본: 압축파일 이름의 폴더) |
| `fctl zip <압축파일> <원본...>` | 압축하기 (`.zip`, `.tar.gz` 등 확장자로 형식 결정) |
| `fctl flatten <타겟>` | 하위 폴더의 파일을 타겟 바로 아래로 옮기고 빈 폴더를 휴지통으로 보내기 |
| `fctl product-number <타겟>` | 영상 파일 이름 앞에 제품번호 넣기 |
| `fctl extract-all <타겟>` | 압축 파일마다 새 폴더에 풀기 |

옵션

- `--force`: 이미 있는 파일을 덮어쓴다. 없으면 덮어쓰기 대신 오류를 내고 멈춘다.
- `--permanent`: `rm`에서 휴지통을 거치지 않고 영구 삭제한다.
- `--dry-run`: 바뀔 내용만 `[미리보기]`를 붙여 출력하고 실제로는 건드리지 않는다.

모르는 옵션은 아무것도 실행하지 않고 오류를 낸다. `-`로 시작하는 이름은 `./-이름`처럼 쓰거나 `--` 뒤에 쓴다(`fctl rename a.txt -- "-b.txt"`). `--` 뒤의 인자는 모두 옵션이 아닌 이름·내용으로 본다.

PowerShell에서는 `-b.txt`처럼 따옴표 없는 대시 이름을 `-b`와 `.txt`로 나누므로 `./-이름`을 쓰거나 이름을 따옴표로 감싼다. `npm link`로 등록한 `fctl`을 PowerShell에서 부르면 `--`가 사라질 수 있으니(`npm link` 심과 비슷하게 만든 스크립트에서 확인), `--`가 필요하면 `node bin/fctl.js`로 직접 실행한다.

`write`, `append`의 내용은 `- 항목`처럼 `-` 하나로 시작해도 되지만, `--`로 시작하는 내용과 `-h`는 `--` 뒤에 쓴다(`fctl write a.txt -- "--- 제목"`). 내용 자리의 `-dry-run` 같은 오타는 내용으로 쓰이므로 주의한다.

## 안전 장치

- 삭제는 기본적으로 휴지통으로 보내므로 되돌릴 수 있다. 대화형 세션이 아니면(서비스, 예약 작업) 영구 삭제가 되지 않도록 거부한다.
- 쓰기·이름 변경·이동·복사·압축은 대상이 이미 있으면 `--force` 없이는 덮어쓰지 않는다.
- 다른 드라이브로 옮길 때는 복사가 끝난 뒤에 원본을 지운다.
- `mv`는 전체를 먼저 검사해서 원본과 대상이 겹치거나, 여러 원본이 같은 대상으로 모이거나, 현재 폴더를 옮기려 하면 아무것도 옮기지 않고 오류를 낸다.
- `mv --force`는 기존 대상을 지우지 않고 잠시 치워 두었다가 이동이 끝난 뒤에 지운다. 이동이 실패하면 되돌린다.
- `zip`은 압축 파일 자신을 묶으려 하면 아무것도 지우기 전에 오류를 낸다.
- `zip`은 임시 이름으로 묶은 뒤 기존 압축 파일과 바꾼다. 실패하면 기존 압축 파일을 되돌린다.
- `unzip`은 암호를 묻지 않는다. 암호가 걸린 압축 파일은 실패한다.
- `zip`과 `unzip`은 경로나 묶을 폴더 안의 이름에 시스템 코드페이지에 없는 문자(이모지, 한국어 Windows의 `é`, macOS에서 온 한글 자모 등)가 있거나 이름 끝이 점이나 공백이면 실행하지 않고 오류를 낸다. `tar.exe`가 이런 이름을 다른 글자로 바꿔 다른 파일을 다룰 수 있기 때문이다.
- `--dry-run`은 없는 경로, 덮어쓰기 충돌, 자기 안으로 이동 등 실패할 작업을 미리 알려 준다. 다만 권한, 디스크 공간, 파일 잠금, Windows에서 쓸 수 없는 이름, 링크·정션을 거치는 경로, 복사하는 폴더 안쪽의 충돌, 현재 폴더나 그 상위의 이름 변경, 압축 내용의 손상과 충돌은 실제로 실행해야 알 수 있다.

## 평탄화

`fctl flatten <타겟>`은 하위 폴더의 파일을 타겟 바로 아래로 옮긴다. 먼저 `--dry-run`으로 확인할 수 있다.

- **덮어쓰지 않는다.** 이름이 겹치면 `a (2).mkv`처럼 번호를 붙인다. `--force`는 쓰지 않는다.
- **이름**: 파일이 그 폴더의 유일한 파일이고 폴더명이 더 자세하면 폴더명을 쓴다. `ABC-123 제목/abc_123.mp4`는 `ABC-123 제목.mp4`가 된다. 판단이 서지 않으면 파일 이름을 유지하고, 확장자는 바꾸지 않는다.
- **저장소는 거부한다.** 타겟 아래에 `.git`, `.hg`, `.svn`, `.jj`나 베어 저장소가 있거나 타겟이 그 안이면 아무것도 옮기지 않고 오류를 낸다. 타겟이 저장소의 일반 하위 폴더(`r/src`)면 거부하지 않는다. 저장소는 망가지지 않고 추적 파일은 git으로 되돌릴 수 있지만, 미추적 파일은 되돌릴 수 없다.
- **옮기지 않는 항목**: 링크, Windows에서 해석이 갈리는 이름(끝 점·공백, `Con.Air.mkv` 같은 장치 이름), `.fctl-old-*`·`.fctl-new-*` 잔여물, `$RECYCLE.BIN`·`System Volume Information` 안의 파일. 사유와 함께 보고한다.
- **되돌리는 기능은 없다.** `node_modules` 같은 프로그램 폴더, `desktop.ini`, `Thumbs.db`도 일반 파일처럼 옮기므로 먼저 `--dry-run`으로 확인한다.
- `--dry-run`의 이름은 실행 때 바뀔 수 있다. 앞 파일을 옮기면서 8.3 짧은 이름이 새로 차면 번호가 붙는다.
- **실패**: 잠긴 파일 등으로 한 파일이 실패해도 나머지는 계속 옮기고, 실패 목록을 보여 준 뒤 종료 코드 1로 끝난다.
- **빈 폴더**: 이번에 옮긴 파일이 있던 폴더가 비면 휴지통으로 보낸다. 그 안의 빈 폴더도 함께 간다. 원래 비어 있던 다른 폴더(`Inbox/`)는 건드리지 않는다. 건너뛰었거나 실패한 파일이 남은 폴더, 잔여물·시스템 폴더, 현재 폴더와 그 상위는 남긴다. 지우지 못한 폴더가 있으면 종료 코드 1로 끝난다. 폴더가 많으면 오래 걸린다.
- 보호 경로(`C:\Windows`, 사용자 폴더 자체, `AppData` 등)는 타겟으로 쓸 수 없다.

## 제품번호 넣기

`fctl product-number <타겟>`은 타겟 아래 영상 파일의 이름 앞에 제품번호를 넣는다. `ABC-123 제목/video.mp4`는 `ABC-123 제목/ABC-123 video.mp4`가 된다. 파일을 옮기지는 않는다. 먼저 `--dry-run`으로 확인할 수 있다.

- **형식**: `ABC-123`처럼 영문 2~6자, 하이픈, 숫자 2~5자. 자세한 규칙은 `src/product.js`에 있다.
- **대상**: 영상 확장자의 파일만 바꾼다. `.ts`, `.mts`는 내용이 전송 스트림일 때만 영상으로 본다. TypeScript 소스를 바꾸지 않기 위해서다.
- **찾는 곳**: 파일명, 메타데이터 제목, 폴더명(타겟 아래, 가까운 폴더부터), 코멘트 순이다. 메타데이터는 MP4 계열(`.mp4`, `.m4v`, `.mov`, `.3gp`)만 읽는다.
- **이미 번호가 있으면** 위치에 관계없이 건너뛴다. 넣으려는 번호와 같으면 대소문자가 다르거나 글자가 붙어 있어도(`ABC-123-01`, `abc-123`) 있는 것으로 본다.
- **파일명의 소문자 말**(`trip-2023`, `intro-01`)은 번호인지 확실하지 않다. 제목, 폴더, 코멘트에 다른 번호가 있으면 고르지 않고 엇갈림으로 보고한다.
- **못 찾으면** 건드리지 않고 목록으로 보고한다. 제목과 폴더의 번호가 엇갈려도 고르지 않고 보고한다. 링크는 바꾸지 않고 보고한다.
- **덮어쓰지 않는다.** 같은 이름이 있으면 건너뛰고 보고한다.
- **되돌리는 기능은 없다.** OneDrive 온라인 전용 파일은 메타데이터를 읽을 때 내려받기가 일어날 수 있다. `.ts`, `.mts`는 이름과 상관없이 앞부분을 읽으므로 번호가 없는 소스 파일에서도 일어날 수 있다.

## 압축 파일 모두 풀기

`fctl extract-all <타겟>`은 타겟 아래 압축 파일(`.zip`, `.tar`, `.tar.gz`, `.tgz`, `.tar.bz2`, `.tbz2`, `.tar.xz`, `.txz`, `.7z`, `.rar`)을 각각 옆의 새 폴더에 푼다. `a.zip`은 `a/`가 된다. 먼저 `--dry-run`으로 확인할 수 있다.

- **압축 파일은 기본으로 남긴다.** 풀려 나온 압축 파일을 다시 풀지도 않는다.
- **`--remove-archives`**: 정상으로 풀린 `.zip`, `.7z`를 휴지통으로 보낸다. 건너뛰거나 실패한 압축 파일은 지우지 않는다. 그래서 이미 풀어 둔 폴더가 있으면 원본도 남는다.
- **이 옵션으로도 남기는 경우**: 아래는 풀기만 하고 "남김"으로 보고한다.
  - 다른 형식(`.tar`, `.tar.gz`, `.tgz`, `.tar.bz2`, `.tbz2`, `.tar.xz`, `.txz`, `.rar`). `tar.exe`가 손상을 잡지 못하거나 일부를 읽지 않거나, 잡는지 확인하지 못했다.
  - 내용이 확장자와 다른 파일, 끝이 잘렸거나 앞뒤에 다른 데이터가 붙은 `.zip`, 뒤에 다른 데이터가 붙은 `.7z`, 분할 압축 조각, Zip64 형식의 `.zip`.
  - 원래 이름 그대로 풀렸는지 확인하지 못한 경우. `:`나 `?`가 든 이름, UTF-8 표시가 없는 비ASCII 이름의 `.zip`, 비ASCII 이름의 `.7z`가 해당한다. 한국어 도구나 `fctl zip`으로 만든 한글 이름의 `.zip`도 여기에 들 수 있다.
- **휴지통 주의**: 휴지통 용량을 넘는 큰 파일이나 휴지통이 없는 볼륨에서는 Windows가 묻지 않고 영구 삭제할 수 있다. 시험하지는 못했다. 내용은 새 폴더에 풀려 있다.
- **합치지 않는다.** 같은 이름의 폴더나 파일이 있으면 건너뛰고 보고한다. 그래서 다시 실행해도 또 풀리지 않는다.
- **전부 풀린 것만 내놓는다.** 임시 폴더(`.fctl-new-*`)에 푼 뒤 이름을 바꾼다. 실패하면 임시 폴더를 지우고 실패로 보고한다.
- **실패로 보는 경우**: 깨진 압축 파일, 암호가 걸린 압축 파일, 항목이 하나도 없는 파일, `..`로 타겟 밖을 가리키는 항목, 이름이 겹쳐 일부를 잃는 항목(대소문자만 다른 경우 포함), `con.txt`나 끝이 점인 이름처럼 Windows에서 다르게 해석되는 이름, 링크와 장치 항목.
- **잡지 못하는 손상**: `.tar.gz`는 본문이 일부 변해도 성공할 수 있고, `.tar`는 항목 경계에서 잘리면 남은 항목만 풀고 성공한다. `.zip`도 끝이 잘리거나 다른 파일이 이어 붙으면 일부만 풀고 성공할 수 있다. 풀기는 성공으로 보고하되 위 기준에 따라 원본은 지우지 않는다.
- **미리보기는 목록만 읽는다.** 암호, 이름 겹침, 쓸 수 없는 이름은 실제로 풀어야 알 수 있다.
- **항목 이름**: `tar.exe`가 처리한다. 이모지처럼 코드페이지에 없는 문자가 있거나, Linux·macOS에서 만든 tar에 UTF-8 이름이 그대로 들어 있으면 실패할 수 있고(미리보기는 통과할 수 있다), `:`, `?`, `*` 같은 문자는 `_`로 바뀌거나 이름 앞부분이 사라질 수 있다.
- **크기 제한은 없다.** 풀린 크기를 미리 확인하지 않으므로 디스크가 찰 수 있다. OneDrive 온라인 전용 압축 파일은 읽을 때 내려받기가 일어날 수 있다.
